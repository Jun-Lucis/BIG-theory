## Current release practice

Later scientific outputs are primarily archived as **Zenodo publications with DOI**, with GitHub used for:

- repository-level navigation;
- living documentation;
- paper-entry summaries;
- status maps;
- citation guidance;
- reproducibility-oriented source organization.

If a future GitHub Release is created as a current repository snapshot, its title and body should preserve the distinction between:

```text
structural / formal comparability
    !=
programme-wide quantitative universality
```

and should link back to the integrated status map rather than restating one selected positive result as the state of the whole programme.
